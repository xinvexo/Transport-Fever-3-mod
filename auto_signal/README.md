# 自适应铁路信号灯

《狂热运输 3》的独立 mod，ID 为 `xin_auto_signal_1`。放置一盏铁路信号灯后，自动找出所在的连续轨道区段，并按最小间距重新均匀布置信号灯。

## 使用

启用本 mod 后，打开铁路信号灯建造工具：

- **自动布置**：默认开启。关闭后恢复普通手动放置，并隐藏最小间距设置；再次开启时保留之前的间距值。
- **最小间距**：50～2000 米，默认 300 米。拖动滑块或点击右侧数值直接输入整数米，实际间距可以大于设定值。

开启时，点击位置用于选择区段及信号灯类型、朝向，手动放下的信号灯也参与重新布置。例如可放置范围长 1050 米、最小间距为 300 米时，布点为 0、350、700、1050 米。

区段内同向旧信号灯会被统一替换。新灯继承本次放置信号灯的型号、朝向和单向属性；反向信号灯及其他轨道对象保留。

若均分位置被游戏拒绝，程序会自动尝试移动整组灯位，并始终保持设定的最小间距。优先保持灯数，必要时尝试少一盏；最多提交九种不同方案，成功后立即停止。建造失败不会删除原灯，调整期间轨道区段发生变化则停止本次任务。

界面支持简体中文和英文，随游戏语言切换。

修订 15 为间距控件分配独立的格式化函数标记，避免 Lua 5.2 复用函数时把其他普通控件误识别为间距控件。

## 处理范围

程序向两侧识别无分支的连续轨道，遇到道岔、结构所属轨道或轨道末端停止。区段使用固定的节点顺序来确定计算方向，因此在同一区段以相同设置和朝向点击不同位置，布局保持一致。也支持没有分支的环线。

普通区段两端默认各留 10 米；极短区段的留距缩减为区段长度的 10%。各轨道接缝附近留出 0.5 米，道口和岔道附近遵循信号灯型号要求的留距。程序在剩余可放置范围内选择满足最小间距的最大可行数量，并尽量均匀分配位置。很短的可用范围只放一盏灯。

最多遍历 5000 段轨道，超过时不执行自动重排。每次最多自动布置 1000 盏灯；达到数量限制后仍覆盖整个区段，实际间距相应增大。

轨道网络和信号方向查询结果只在单次规划中复用；每次重试重新读取，提交建造前也会读取当前轨道对象。禁放区间按距离顺序处理。没有新任务时跳过任务列表处理，等待建造完成期间不重复读取任务队列。

**使用时请禁用原版 Automatic Signal Spacing。** 两者都会响应信号灯建造事件；本 mod 已声明与其不兼容。此 mod 独立运行，无需安装原 mod。

## 打包与安装

以下命令在仓库根目录运行，打包无需安装开发依赖：

```sh
python tools/package_mod.py auto_signal
```

生成 `auto_signal/dist/xin_auto_signal_1.zip`。压缩包外层目录为 `xin_auto_signal_1`，只包含 `mod.json`、`strings.json`、`_metadata/` 和 `content/`，可解压到游戏的本地 mod 目录。产物仅供本地使用，不入库。

也可指定本地 mod 父目录，在打包后安装：

```sh
python tools/package_mod.py auto_signal --install '/path/to/game/mods'
```

安装位置为 `/path/to/game/mods/xin_auto_signal_1`。更新时只替换该 mod 的四项资源；如果同名目录的 `mod.json` 无法确认属于本 mod，安装会报错。开发环境和测试文件不会安装到游戏目录。

## 开发与验证

Windows/macOS 共用仓库根目录的开发环境和依赖，配置方法见[项目说明](../README.md#开发测试)。游戏运行不需要这些依赖。在仓库根目录运行：

```sh
python tools/test_mods.py auto_signal
```

Lua 脚本位于 `content/`。`spacing.lua` 负责在允许区间内布点，`network.lua` 负责轨道区段识别，事件脚本负责读取设置并提交建造操作。语言文本位于 `strings.json`。

目前验证范围为 Lua 算法和模拟游戏接口的测试，**尚未在游戏内实测**。真实游戏中的批量建造结果、界面交互，以及弯道上的实际放置距离仍需进游戏确认。

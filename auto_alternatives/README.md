# 自动备用站台

《狂热运输 3》独立 mod，ID：`xin_auto_alternatives_1`。

启用后，自动为线路新添加的停靠站补选备用位置。保留已选主站台，在同一站点组内，把运输方式和客货用途匹配的其他站台设为备用。已有停靠站保留用户的备用和“不使用”选择。

适用于公交、货车、有轨电车、船舶、飞机和直升机的车站内站台。火车（含电力火车）以及路边单侧、双侧停靠点不参与自动备用。同一站点在线路中出现多次时，各次停靠分别处理。

## 使用

1. 将 `dist/xin_auto_alternatives_1.zip` 解压到游戏本地 mod 目录，确保该目录下出现 `xin_auto_alternatives_1/mod.json`。
2. 在存档的模组列表中启用“自动备用站台”，进入游戏。
3. 在线路管理器中添加停靠站。原版完成主站台分配后，其余匹配位置会随本次线路保存一起补为备用，无需逐个勾选。随后可以手动把任意备用站台改为“不使用”。

线路编辑时只处理正在提交的线路。站台扩建时，对比施工前后的车站和站台标识，只给经过该站的线路补选新增站台。一次扩建影响多条线路时，每次游戏更新最多处理 8 条，直到完成。暂停时编辑也可生效。

每次操作重新读取站点和站台数据。已有站台更换实体或调整数组顺序时，按原版站台标识识别新增位置。需要补选备用或移除与首选重叠的备用记录时才提交线路更新，空闲时只检查待处理状态。

已有线路保留当前选择，扩建只补选新站台；延长原站台不会重新勾选已停用的位置。

手动选择的备用及“不使用”位置会保留。切换首选时，新首选从备用列表中移除，符合条件的旧首选会补为备用。主站台、停靠顺序、途经点、装卸过滤、等待时间和线路优先级保持现有设置。

可在原版线路面板中直接手动管理已有站台，也可以在存档的模组列表中停用本 mod；已写入的备用设置仍保留。请避免同时启用其他自动修改同一线路站台设置的 mod。

## 匹配范围

- 火车线路在添加停靠站、切换首选及站台扩建时均不参与自动设置；已有火车备用设置由玩家在原版线路面板中管理。
- 路边单侧、双侧停靠点按游戏的道路附属站点类型排除；普通车站不受站台数量限制。若主停靠位置是路边停靠点，则跳过该次停靠；若候选位置是路边停靠点，则不自动添加为备用。已有备用设置不会自动清除。
- 候选位置必须与主站台同属一个站点组，并支持相交的线路运输方式。
- 候选位置必须至少具有一项与主站台相同的客运／货运装卸能力。
- 主站台尚未确定或暂时不存在时，等待游戏完成分配后再处理。
- 本 mod 自动完成备用勾选，不执行车辆调度。路网连通性、方向、站台长度、电气化和货物专用设施等限制仍由游戏判断；匹配类型不等于保证车辆可达。若游戏显示无路径，可以调整站场连接，或把对应站台设为“不使用”。

## 打包

```sh
python3 tools/package_mod.py
```

输出 `dist/xin_auto_alternatives_1.zip`，只包含游戏资源。也可以指定本地 mod 父目录进行安装：

```sh
python3 tools/package_mod.py --install "/path/to/game/mods"
```

## 测试与接口依据

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -s tests -v
```

实现依据本机游戏的 API 声明及原版线路管理界面：通过 `ModEntryPointExtension` 在 React 界面环境中扩展 `line_util.autoAssignTerminals`，仅为未初始化备用列表的新停靠补选；扩建订阅 `onPreBuildProposal` 和 `onPostBuildProposal`，比较 `Station.tag` 与 `Terminal.tag`，通过 `getLineStops` 查询关联线路。`api.type.Line.new` 保留已有线路配置，`api.type.StationTerminal.new` 使用从 0 开始的站台索引，`api.cmd.makeLineUpdateCmd` 提交扩建后的定向更新。公开参考：[脚本命令文档](https://wiki.transportfever3.com/script-doc/api/cmd.html)。

线路编辑与车站扩建的基本功能曾经过游戏内验证；手动选择保留、扩建差集、事件队列和交通方式匹配通过模拟游戏接口测试，当前版本仍需游戏内确认。
